# 경기 분석 데이터

카메라(폰)와 분석 데스크(PC)가 본 랠리를 대회 기록과 따로 저장하고, 기술·코스·랠리 길이 분석을 계산합니다. 대회 기록(`tournament.json`)과 점수 흐름(rev, PIN, 409 순서)은 건드리지 않습니다. 분석 쓰기가 실패해도 점수는 그대로 남습니다.

코드: `analysis-store.js`(저장, 라우트), `public/analysis.js`(순수 계산. 서버, 화면, 시험이 함께 씀), `scripts/seed-analysis.js`(화면 시험용 데이터).

## 저장

- 파일: `data/analysis/t-<createdAt의 숫자만>.json` = `{ v: 1, tournament: <createdAt>, matches: { <matchId>: { rallies: { <포인트 번호>: { live?: Rally, desk?: Rally } } } } }`. 대회마다 파일 하나이고, 임시 파일에 쓴 뒤 이름을 바꿔 원자적으로 씁니다. 파일 형식은 `v`로 구분합니다.
- 갤러리 경기(다음 단계)는 `data/analysis/g-<id>.json` = `{ v: 1, source: "gallery", id, playedAt, title, rallies: [Rally] }`로 둘 예정입니다. 아직 쓰지 않습니다.
- Rally = `{ v:1, index, source:"live"|"desk", startedAt(ms), durationMs, winner:"near"|"far"|null, nearSlot:0|1, why, shots, bounces }`
- shots[] = `{ side, t, stroke:"포핸드"|"백핸드"|null, kind:"서브"|"스매시"|"드라이브"|"푸시"|"로빙"|null, speedKmh, arc, inferred, land:{tx,ty}|null }`. 샷에는 자세(`pose`)가 없습니다. 보내도 저장하지 않습니다.
- bounces[] = `{ tx, ty, side, t }`. 코트 보정 전 바운드는 `tx`, `ty`가 null이고 분석에서 뺍니다.
- `source`: `live`는 폰 카메라가 랠리 끝에 한 번 보내는 샷 요약이고, `desk`는 PC 분석 데스크가 영상 원본을 다시 돌린 결과입니다. 보낼 때 빠지면 `live`입니다. 같은 경기와 번호에 둘이 오면 덮어쓰지 않고 함께 두고, 같은 `source`로 다시 보내면 그 칸만 바뀝니다. 읽을 때 `source`가 없는 옛 랠리(칸 없이 바로 Rally로 저장된 것)는 `live`로 읽습니다.
- `nearSlot`은 그 랠리 때 가까운 쪽에 선 대회 선수 칸입니다. 엔드가 바뀌어도 이 값으로 누구의 샷인지 정합니다.
- 서버는 위 필드만 골라 저장하고 나머지는 버립니다. 랠리 하나에 샷 200개, 바운드 400개까지 받습니다.
- 정확도 표: `data/analysis/accuracy.json` = `{ <기술>: { precision, recall, n } }`. 없거나 깨졌으면 읽기 응답의 `accuracy`가 null입니다.

## 라우트

| 요청 | 설명 | 응답 |
|---|---|---|
| `POST /api/analysis/rally` | 헤더 `x-pin`, 본문 `{ matchId, index, rally }`. `rally.index`는 `index`와 같아야 합니다 | 200 `{ ok: true }` |
| `GET /api/analysis/match/:matchId` | 지금 대회. PIN 없이 읽습니다 | 200 `{ rallies, accuracy }` |
| `GET /api/analysis/history/:id/:matchId` | 지난 대회. `id`는 `/api/history`와 같은 번호이거나 `current`입니다 | 200 `{ rallies, accuracy }` |

쓰기 실패: 카메라 열쇠 또는 PIN 오류 403(`/api/action`과 같은 규칙, 카메라 열쇠는 PIN 잠금 횟수에 세지 않음), 형식 오류 400, 대회가 없거나 `createdAt`이 없는 옛 대회 409, 없는 경기나 `index`가 점수 수 이상이면 404입니다. 쓰기마다 `action.log`에 한 줄 남깁니다(본문과 PIN은 남기지 않음). rev는 바뀌지 않습니다.

읽기 응답의 `rallies`는 포인트 번호 순서이고, 한 번호에 live와 desk가 있으면 둘 다(live 먼저) 들어 있습니다. 어느 쪽을 쓸지는 `analyzeMatch`가 정합니다.

읽기 실패: 없는 기록 번호 404, 형식이 틀린 번호 400입니다. 없는 경기는 `rallies: []`로 답합니다.

- 실행 취소: 점수 수(`points.length`) 이상인 번호의 랠리는 읽을 때 버립니다. 같은 번호로 다시 쓰면 덮어씁니다.
- 옛 기록: 분석 파일이 없으면 `rallies: []`입니다. 기존 파일은 고치지 않으므로 이전 작업이 없습니다.
- 깨진 파일: JSON이 깨졌거나 `v`가 1이 아니면 파일마다 한 번 로그를 남기고 `rallies: []`로 답합니다. 그 대회에 새 랠리를 쓰면 깨진 파일은 `<파일>.bad-<시각>`으로 옮겨 두고 새로 시작합니다.

읽는 데이터는 좌표와 숫자뿐이고 얼굴이나 영상은 없습니다.

## 기술과 코스 기준

- 서브: 랠리의 첫 샷입니다(`rally.js` 규칙, `kind`가 서브).
- 공격: `kind`가 스매시나 드라이브입니다(속도 22 km/h 이상이고 높은 궤적이 아님). 수비: 푸시나 로빙입니다.
- 포핸드/백핸드: `stroke`(비전 `strokeSide`)입니다. 포즈가 없으면 null입니다.
- 기술 키: `fore-attack`, `fore-defence`, `fore-serve`, `back-attack`, `back-defence`, `back-serve`. `stroke`나 `kind`가 null이면 기술이 정해지지 않아 `unclassified`로 세고(득점자를 모르는 랠리 포함) 성공률에서 뺍니다. 화면에는 '판정 못 한 샷 n개'로 보여 줍니다.
- 성공: 득점자가 정해진 랠리에서 랠리의 마지막 샷을 친 쪽이 실점했을 때만 그 샷이 실패이고, 나머지 샷은 모두 성공입니다(상대가 받아 넘겼거나 득점으로 끝났습니다). 득점한 쪽이 마지막에 쳤으면 실패한 샷은 없습니다(상대가 못 받음). 득점자를 모르는 랠리는 성공, 길이, 서브, 타임라인에서 뺍니다.
- 9칸: 그 샷이 상대 코트에 떨어진 자리(`land`)로 `zones[slot][row][col]`에 셉니다.
  - 깊이(row): 네트에서 상대 끝선까지 1.37 m를 3등분합니다. 0 짧음(0~0.457 m), 1 중간, 2 깊음입니다.
  - 좌우(col): 1.525 m 폭을 3등분합니다. 0 왼쪽, 1 가운데, 2 오른쪽이고 친 사람이 보는 방향 기준입니다. `ty`는 가까운 쪽에서 볼 때 왼쪽이 0이므로(코트 보정이 내 쪽 왼쪽 모서리부터 찍음) 먼 쪽 선수는 뒤집어 계산합니다.
  - 경계 위의 점은 더 깊은 칸, 더 오른쪽 칸으로 갑니다. 네트 선 위(`tx`=1.37)는 양쪽 모두 짧음입니다. 자기 코트나 탁구대 밖에 떨어진 값은 칸에 넣지 않습니다.
- `bounces[].slot`: 그 바운드 직전에 공을 친 선수입니다. 앞선 샷이 없으면 공이 튄 쪽 선수(자기 코트에 튄 서브)입니다.
- 랠리 길이: 샷 수로 1~2구(서브·리시브), 3~4구, 5~6구, 7구 이상입니다. 샷을 하나도 못 본 랠리는 세지 않습니다.
- 서브 득점: 첫 샷을 친 선수가 서버입니다. `serve[slot]`은 그 선수가 서브한 랠리 수와 이긴 수입니다. 리시브 득점은 상대의 `serve`에서 뺀 값입니다.
- 정확도가 낮은 기술: 시험 정답과 비교한 재현율이나 정밀도가 0.7보다 낮으면(정확히 0.7은 낮지 않음) `estimateFrom(accuracy)`가 true를 줍니다. 표에 없는 기술도 true입니다. `accuracyStatus(accuracy, key)`는 화면용 세 상태를 줍니다: 정답 n이 5 미만이거나 표에 없으면 `sample`(화면은 숫자 대신 '표본 부족'), 정밀도가 null이거나 정밀도·재현율이 0.7 아래면 `estimate`(숫자와 '추정'), 그 밖은 `measured`(숫자만)입니다. 정확도 표가 없으면 화면은 폰 쪽 기술 6종을 모두 '추정'으로 둡니다.

## 계산 결과

`analyzeMatch(rallies, { pointsLen, clips })`:

- 포인트마다 랠리 하나만 씁니다. 같은 번호에 desk가 있으면 desk를, 없으면 live를 씁니다.

- `top5`: 샷 수가 많은 순서입니다. 같으면 오래 걸린 랠리, 그다음 앞선 번호입니다. 득점자를 모르는 랠리도 들어갑니다. `winner`는 선수 칸(0, 1) 또는 null이고 `clip`은 그 포인트의 클립 주소 또는 null입니다.
- `timeline`: 선수 칸마다 이긴 포인트 번호입니다.
- `reportBy`: 선수 칸마다 `{ slot, text }` 또는 null입니다. `report`는 그중 앞선 값입니다.
- `reportLine(analysis, slot)`: 서브 득점률, 리시브 득점률, 기술별 성공률, 길이별 승률 가운데 표본이 5개 이상인 것 중 가장 낮은 하나를 골라 숫자와 다음 연습을 한 문장으로 말합니다. 같으면 이 순서에서 앞선 것입니다. '가장 낮다'는 다른 항목이 실제로 더 높을 때만 말하고, 모두 같으면 100%일 때 표본이 가장 많은 항목을 칭찬하며 '아직 약점이 안 보여요', 100% 아래면 비율만 말합니다. 성공률은 승자가 정해진 포인트의 샷만 세므로, 그런 포인트(`analysis.decided`)가 5개(`REPORT_MIN_N`)보다 적으면 '아직 득점이 정해진 포인트가 적어요(N개).'를 돌려줍니다. 랠리가 하나도 없거나 표본 5개 이상인 항목이 없으면 null입니다.

## 폰과 PC의 역할, 자세 데이터

- 폰(카메라 모드)은 실시간 점수와 오버레이를 맡고, 랠리가 끝나면 이미 만든 샷 요약(쪽, 시각, stroke, kind, 속도, arc, 바운드)만 한 번 보냅니다(`source:"live"`). 계산을 더하지 않고 자세도 보내지 않습니다. `rally.js`, `pipeline.js`, `players.js`는 고치지 않습니다.
- PC(분석 데스크)는 영상 원본을 GPU로 다시 돌려 정밀 2D 자세, 3D 몸 모양, 기술 재분류를 만듭니다(`source:"desk"`). 계산은 desk를 먼저 씁니다. 데스크 모드, 대기열(`data/desk/queue.json`), `desk-worker`는 3단계에서 만듭니다.
- 자세(`pose2d`)는 데스크가 만들고 경기 파일이 아니라 `data/analysis/pose/<경기키>.json`에 따로 둡니다(5단계): `{ model, at:[-0.77,-0.4,0], frames:[[ [x,y,v] × 23 ] 또는 null × 3] }`. 몸 관절 23개(코와 11~32번)만 쓰고 얼굴 점은 버리며, 양 엉덩이 가운데를 원점으로 몸통 길이를 1로 맞춥니다. 기준 시각은 공을 맞힌 순간과 0.77초 전, 0.4초 전입니다.
- 선수 이름별 저장(`이름,네자리`, `data/analysis/players.json`)과 선수 페이지는 4단계입니다. 3D(`data/analysis/pose3d/`)는 6단계이고, 단일 카메라라 깊이는 추정이라고 화면에 적습니다.
- 이번 단계에는 위 파일들이 없습니다.

## 화면 시험 데이터

```bash
bun scripts/seed-analysis.js --out=/tmp/pp-demo   # 운영 data 폴더나 대회가 이미 있는 폴더는 거절해요
PORT=8799 DATA_DIR=/tmp/pp-demo bun server.js
```

첫 경기가 끝난 시험 대회와 합성 랠리 23개(긴 랠리, 판정 못 한 샷, 득점자 모름 1개, 클립 4개)가 들어갑니다. 6번과 12번 포인트에는 모든 샷을 분류한 desk 랠리가 live와 함께 있습니다. PIN은 그 폴더의 `tournament.json`에만 있습니다.

## 화면: 경기 분석

코드: `public/analysis-view.js`(화면 하나, 순수 그리기), `public/app.js`의 훅(가져오기 한 줄, `viewOf`·`goUp`·popstate·`render`·`screenName`·뒤로 버튼 각 한 줄, 진입 버튼 둘, `bindAnalysis` 한 번), `public/style.css`의 `경기 분석` 블록.

- 들어가는 곳: 경기 화면의 `분석` 버튼(포인트가 하나라도 있는 경기), 기록 상세의 경기 카드마다 `분석` 버튼. 둘 다 화면 스택에 쌓여 왼쪽 위 뒤로와 브라우저 뒤로가 같은 곳으로 돌아가요. 새로 고침하면 앱의 다른 화면처럼 그 위 화면(경기 또는 기록)으로 돌아가요.
- 데이터: 지금 대회는 `GET /api/analysis/match/:matchId`, 기록에서 열면 `GET /api/analysis/history/:id/:matchId`(`id`는 `/api/history`의 번호, 지금 대회는 `current`). 받은 랠리를 `analyzeMatch(rallies, { pointsLen, clips })`로 그 자리에서 계산해요. 포인트 수가 바뀌면(새 점수, 점수 취소) 다시 받아요. 받은 적 없으면 '불러오는 중', 실패하면 원인과 `다시 시도`.
- 나 고르기: 두 선수 이름 세그먼트. 고른 칸은 `localStorage` `pp-analysis-me`(0 또는 1, 기본 0)에 남고 이 기기의 모든 경기에 적용돼요. 표와 지도는 나를 먼저, 상대를 다음에 둬요.
- 빈 화면: 랠리가 하나도 없으면 왜 없는지(카메라 모드로 찍은 포인트만 분석할 수 있음, 아직 보낸 랠리 없음 또는 카메라 없이 기록됨)와 `다시 불러오기` 하나만 보여요.

### 브리프
- 주된 동작: 랠리 `다시 보기`(가장 긴 랠리 5개의 버튼, 득점 흐름의 칩). 모두 기본 버튼 모양이고 크기가 같아요. 강조색 버튼은 빈 화면·오류의 `다시 불러오기`·`다시 시도` 하나뿐이에요.
- 읽는 순서: 1 나의 한 줄 리포트(가장 낮은 수치와 다음 연습), 2 기술 성공률 나 vs 상대, 3 코스(바운드 자리, 9칸). 그다음 랠리 길이별 승률, 가장 긴 랠리 5개, 득점 흐름.
- 일부러 뺀 것: 숫자 타일, 제목마다 붙는 부제, 장식 배지, 색 막대, 샷 속도 그래프, 카드 테두리 강조. 랠리 수와 포인트 수는 나 고르기 아래 한 문장에 넣어요.
- 꼭 있는 내용: 경기 번호·이름·두 선수, 나 고르기(두 이름), 랠리 수·포인트 수, 선수별 한 줄 리포트(없으면 '표본 5개 이상 없음' 문장, 승자가 정해진 포인트가 5개보다 적으면 '아직 득점이 정해진 포인트가 적어요(N개)'), 바운드 지도(범례 모양+개수, 카메라 쪽·네트·먼 쪽 표시, 글 대체), 선수별 9칸(칸마다 개수와 %, 깊이·좌우 이름, 네트 쪽 표시, 떨어진 공 수), 기술 표 6줄(성공률과 성공/시도 또는 '표본 부족', 표 머리에 작게 '(포인트 N개 기준)', 승자가 정해진 포인트가 5개보다 적으면 모든 칸이 '알 수 없음'과 그 뜻을 말하는 문장, `추정` 배지, 판정 못 한 샷 수, 정확도 표가 있으면 거짓 샷 문장(공개 시험 클립에서 찾은 샷 101개 중 59개)과 '정확도: 공개 데이터셋 정답 기준'), 길이별 표 4줄(랠리 수, 선수별 승률과 승수), 가장 긴 랠리 5개(순위, 구 수, 초, 포인트 번호, 득점자, 다시 보기 또는 영상 없음), 득점 흐름 두 줄(선수별 이긴 포인트 칩, 영상 있는 칩만 재생 표시와 함께 눌림), 빈 화면·불러오는 중·오류.
- 색만으로 뜻을 전하지 않기: 나는 동그라미(노랑), 상대는 네모(흰 테두리). 9칸은 색 농도와 함께 숫자와 %를 적어요. 영상 없는 칩과 버튼은 흐리면서 재생 표시가 없고 글로 '영상 없음'이라고 해요. 추정은 배지 글자예요.
- 기술 표와 정확도: 서버는 `data/analysis/accuracy.json`이 없으면 앱과 함께 다니는 `analysis-accuracy.json`(공개 데이터셋 정답 기준, 추정 2 · 표본 부족 4)을 주므로 새 배포도 측정 상태로 보여요. 표가 있으면 기술마다 `accuracyStatus`대로 `sample`은 두 선수 칸 대신 '표본 부족' 하나, `estimate`는 숫자와 `추정` 배지, `measured`는 숫자만이에요. 표 아래 정확도 문장은 샷 감지의 거짓 샷(공개 시험 클립에서 찾은 샷 101개 중 59개)을 먼저 말하고, 기술별 정확도는 정답과 맞춘 샷만 센다고 한 뒤 같은 상태로 셈 개수('기술 6종 중 추정 2 · 표본 부족 4', `measured`가 있으면 '· 측정 n')를 적고 '정확도: 공개 데이터셋 정답 기준'으로 끝나요. 어느 표도 안 오면(두 파일 모두 없거나 깨짐) 폰 쪽 기술 6종을 모두 `추정`으로 표시하고 '정확도 표가 아직 없어…'라고만 적어요. 수치는 `stage2/accuracy.md`의 것이고 'human-verified' 같은 말은 쓰지 않아요.
- Layout: 분석 = 위 고정 바 아래 카드 한 열, 스크롤 주인은 문서 하나(안에 스크롤 영역 없음, 고정 바 없음). 1200 px부터는 두 열 격자이고 경기 줄·나 고르기·한 줄 리포트·빈 화면·오류·불러오는 중은 두 열을 가로질러요(`.an-span`). 카드 순서는 읽는 순서 그대로(기술 성공률, 바운드 자리, 코스 9칸, 랠리 길이별 승률, 가장 긴 랠리 5개, 득점 흐름) 예요. 560 px까지 폰 한 열이고 9칸 두 개는 560 px부터 나란히 서요.
- 터치: 버튼·칩·세그먼트 모두 44 px 이상이고 칩 사이는 8 px예요.

## 선수와 달력

### 사람 열쇠

- 사람은 이름과 네 자리로 정합니다. 계정이나 번호는 따로 없습니다. 열쇠는 `홍길동,0712` 문자열입니다.
- 이름은 앞뒤 공백을 없애고 유니코드 표기를 NFKC로 맞춘 뒤 비교합니다. 전각 쉼표 `，`도 쉼표가 됩니다.
- 대회 기록에 `codes`가 있으면 `players[i]`와 `codes[i]`로 열쇠를 만듭니다. 한 대회에 같은 이름이 둘이라 `홍길동·12`처럼 끝자리가 붙어 보이면, 그 끝자리는 화면용이므로 떼고 만듭니다.
- `codes`가 없는 옛 대회는 이름만 열쇠입니다(`홍길동`). 아래의 합치기로 `홍길동,0712`에 붙입니다.
- 갤러리 경기는 올릴 때 고른 `players.near`, `players.far` 열쇠를 씁니다. 이름 없이 올린 쪽은 아무에게도 들어가지 않고 상대 이름은 `이름 없음`으로 보입니다.

### 합치기와 이름 바꾸기

- `data/analysis/players.json` = `{v:1, aliases:{옛열쇠: 새열쇠}}`. 이 파일에만 적고, 대회 기록, 보관 기록, 분석 파일, 갤러리 파일은 한 바이트도 바꾸지 않습니다. 임시 파일에 쓴 뒤 이름을 바꿉니다.
- 읽을 때 열쇠는 연결을 끝까지 따라갑니다(`a → b → c`이면 `c`). 손으로 고친 파일에 고리가 생기면 고리 안에서 가장 작은 열쇠 하나로 모읍니다.
- 파일이 없거나 깨졌거나 v1이 아니면 연결이 없는 것으로 읽습니다. 깨진 파일은 다음에 쓸 때 `players.json.bad-<시각>`으로 옮겨 둡니다.

| 요청 (모두 x-pin 필요) | 하는 일 |
|---|---|
| `POST /api/players/merge` `{from, to}` | `from` 사람을 `to` 사람에 붙입니다. 예: `{from:'홍길동', to:'홍길동,0712'}` |
| `POST /api/players/rename` `{from, toName}` | 네 자리는 그대로 두고 이름만 바꿉니다. `홍길동,0712` → `홍길돈,0712` 연결을 하나 적습니다 |
| `GET /api/players/aliases` | `{aliases}`. 열쇠에 네 자리가 들어 있으므로 PIN 뒤에서만 줍니다 |
| `DELETE /api/players/aliases/:from` | 그 연결 하나를 지웁니다. 되돌리기입니다 |

- 합치기와 이름 바꾸기는 `from`을 지금 가리키는 사람으로 먼저 따라간 뒤 그 사람에서 연결을 적습니다. 그래서 앞서 적은 연결은 그대로 남고, 각 연결을 따로 되돌릴 수 있습니다. 이름 바꾸기도 지금 사람의 네 자리를 씁니다.
- 이미 같은 사람(고리가 생기는 합치기 포함)이면 409, 열쇠나 이름 형식이 틀리면 400, 지울 연결이 없으면 404입니다.
- 되돌리기: 답에 오는 `aliases`나 `GET /api/players/aliases`에서 연결의 왼쪽 열쇠를 보고 `DELETE /api/players/aliases/<그 열쇠>`를 보냅니다(쉼표는 `%2C`로 써도 됩니다). 경기 기록은 손대지 않았으므로 지우는 순간 원래대로 읽힙니다.

### 경기 날짜

- 대회 경기: 그 경기 첫 랠리(가장 작은 index)의 `startedAt`. 랠리가 없으면 보관된 시각(보관 파일 번호), 진행 중 대회면 `createdAt`입니다.
- 갤러리 경기: `playedAt`. 시간대가 없는 값(`2026-10-30`, `2026-10-30T21:00`)은 이미 한국 날짜로 봅니다.
- 날짜는 모두 한국 시간(Asia/Seoul, UTC+9, 서머타임 없음)의 날짜입니다.
- 주는 월요일에 시작하고 그 주 월요일 날짜로 부릅니다. 일요일 23:59 KST와 월요일 00:00 KST는 다른 주입니다. 달은 `YYYY-MM`이고 한국 시간 1일 00:00에 바뀝니다.

### 공개 읽기 (PIN 없음, 이름만)

`ref`는 공개 주소에 쓰는 손잡이입니다. 연결을 따라간 사람 열쇠의 sha256 앞 16자(16진수)이고, 공개 주소에 네 자리가 들어가지 않게 합니다.

`GET /api/analysis/people`: `{people:[{ref, name, label?, matches, lastPlayed}]}`. 경기를 한 사람을 최근 경기 순으로 줍니다. 같은 이름이 둘 이상이면 네 자리가 있는 사람에게 `label`이 붙습니다. 대회 표시와 같은 규칙으로 끝 두 자리(`·12`)이고, 끝 두 자리까지 같으면 네 자리 전부입니다. 코드 없는 옛 사람에게는 `label`이 없습니다.

`GET /api/analysis/person/:ref?month=YYYY-MM&period=week|month` (`month` 기본은 이번 달, `period` 기본은 `month`)

- 모르는 `ref`는 404입니다. 합치기나 이름 바꾸기 뒤의 사람은 새 `ref`를 쓰지만, 기록이나 연결에 남은 옛 열쇠의 `ref`도 지금 사람을 엽니다. 연결이 바뀌어도 도착하는 사람의 `ref`는 그대로입니다.
- 열쇠 주소 `GET /api/analysis/person/홍길동,0712`도 남아 있지만 x-pin이 필요합니다. 머리글이 없으면 PIN 잠금 횟수를 세지 않고 403, PIN이 틀리면 PIN 규칙대로 답합니다.

- `person`: `{ref, name}`. 연결을 따라간 사람의 손잡이와 이름입니다.
- `matches`: 최근 것부터 `{kind:'tournament'|'gallery', id, title, date, opponent, score:{me, them}, won, clips, analysis}`. 대회 경기의 `id`는 `<기록 번호 또는 current>/<경기>`, 점수는 이긴 게임 수입니다. 갤러리 경기의 점수는 랠리 득점 수입니다. 끝나지 않은 대회 경기와 비긴 갤러리 경기는 `won:null`입니다. 점수가 하나도 없는 대회 경기는 넣지 않습니다.
- `analysis`: 랠리가 없으면 `null`. 있으면 그 사람 쪽의 `{n, serve:{n,won}, receive:{n,won}, tech:{기술:{n,ok}}, length:[{label,n,won}], speed:{n,sumKmh}}`. 같은 포인트는 데스크 랠리를 먼저 씁니다.
- `calendar`: `{month, days:[{date, matches:[{kind,id,title,opponent,score,won,clips}], clips}]}`. 경기가 있는 날만 있습니다.
- `trend`: 오래된 기간부터 `[{period, played, won, winRate, tech}]`. 승패가 난 경기만 셉니다.
- `winLoss`: `{won, lost}` 각각 `{matches, serve, receive, tech, length, speed:{n,avgKmh}}`. 비율은 `{n, rate}`이고 경기마다의 비율을 평균하지 않고 n을 모두 더해 냅니다. 그래서 `n`은 그 비율 뒤의 포인트나 샷 수입니다. 분석이 없는 경기와 승패가 안 난 경기는 빠지며, `n`이 0이면 `rate`는 `null`입니다.

`GET /api/analysis/matches`는 이제 점수가 있는 대회 경기(지금 대회와 보관 대회)와 갤러리 경기를 함께 `playedAt` 최근 순으로 줍니다. 대회 경기는 `{kind:'tournament', id, title, playedAt(한국 날짜), players:{near,far}, score:{near,far}}`입니다.

공개 읽기는 이름만 줍니다. 예외는 위의 `label`이고, 끝 두 자리까지 같은 두 사람은 네 자리 전부가 보입니다. `ref`는 소금 없는 해시라 이름을 아는 사람이 1만 번 대입하면 네 자리를 알아낼 수 있습니다. 네 자리는 비밀번호가 아니므로 받아들인 한계이고, 주소와 화면에 드러나지 않게 하는 용도입니다.

## 자세 비교

샷마다의 자세는 분석 데스크만 만듭니다. 폰 카메라는 자세를 보내지 않습니다. 사람별, 기술별로 공 맞는 순간에 맞춰 평균을 내고, 두 기간을 숫자로 비교합니다. 코드는 `public/pose-stats.js`(순수 계산)와 `pose-store.js`(저장)에 있습니다.

### 저장

- 데스크 결과 `POST /api/desk/worker/jobs/:id/result`의 `pose`로 받습니다. `{ [랠리 index]: { [샷 index]: { pose2d, pose3d } } }`이고, 없어도 됩니다. 형식이 틀렸거나 결과에 없는 랠리, 샷을 가리키면 결과 전체가 400입니다.
- `pose2d = {model, at:[-0.77,-0.4,0], hand:'R'|'L'|null, frames}`. `hand`는 데스크가 영상에서 정한 라켓 손이고, 그 끝의 샷이 5개 미만이면 `null`(모름)입니다. `vote`('R'|'L'|null, 없을 수도 있음)는 그 샷 하나의 라켓 손 표입니다(예전 데스크는 보내지 않습니다), `pose3d = {frames}`. `frames`는 기준 시각 3개의 뼈대이고, 볼 수 없던 시각은 `null`입니다. 뼈대는 관절 23개(코, MediaPipe 11~32번)이고 2D 관절은 `[x,y,v]`, 3D 관절은 `[x,y,z,v]`입니다.
- 위치: `data/analysis/pose/<경기키>.json` = `{v:1, rallies}`. 경기 파일이 커지지 않게 따로 둡니다. 경기키는 갤러리면 `g-<일감 번호>`, 대회 경기면 `t-<createdAt 숫자>-<경기>`입니다.
- 임시 파일에 쓴 뒤 이름을 바꾸고, 랠리 단위로 합칩니다. 깨진 파일은 없는 것으로 읽고, 다음에 쓸 때 `<파일>.bad-<시각>`으로 옮겨 둡니다.

### 기준 시각

`at`은 공 맞는 시각에서 몇 초 전인지입니다. 공 맞는 순간(0), 0.4초 전, 0.77초 전 세 장면을 씁니다. 공 맞는 시각은 비전이 본 샷 시각 `t`입니다.

### 정규화

- 뼈대마다 양 엉덩이 가운데를 원점으로 옮기고, 몸통 길이(어깨 가운데에서 엉덩이 가운데까지)를 1로 나눕니다. 그래서 몸 크기와 화면 속 위치, 카메라 거리가 빠집니다. 데스크가 2D를 이미 이렇게 저장하지만, 읽을 때 2D와 3D에 똑같이 다시 합니다.
- 3D는 세로축으로 돌려 엉덩이 선을 +x에 맞춥니다. 어느 쪽 끝에서 쳤든, 카메라가 어디 있든 같은 방향이 됩니다. 몸통 회전은 어깨 선과 엉덩이 선 사이 각이라 그대로 남습니다.
- 2D는 돌릴 수 없으므로, 먼 쪽(`far`)에서 친 샷만 좌우를 뒤집어 가까운 쪽과 같은 방향으로 맞춥니다. 카메라 높이와 각도 차이는 2D에서 지울 수 없습니다.
- 어깨나 엉덩이가 `v<0.5`이면 몸통을 잴 수 없으므로 그 장면은 뺍니다. 다른 관절은 관절마다 `v<0.5`인 장면만 빼고 평균합니다.

### 숫자

평균 뼈대 하나에서 잽니다. 쓰는 관절이 빠졌으면 그 숫자는 `null`입니다. 2D와 3D 양쪽에 대해 같은 식으로 냅니다.

| 숫자 | 뜻 |
|---|---|
| `elbowDeg` | 라켓 손 어깨-팔꿈치-손목의 각. 180이 쭉 편 팔 |
| `kneeBendDeg` | 180에서 엉덩이-무릎-발목의 각을 뺀 값. 0이 쭉 편 다리. 보이는 다리의 평균 |
| `trunkRotationDeg` | 어깨 선과 엉덩이 선 사이의 각 |
| `handHeight` | 라켓 손 손목이 엉덩이 가운데보다 높은 정도. 몸통 길이 단위, 위가 양수 |

라켓 손은 그 기간 샷에 가장 많이 적힌 `hand`입니다(`null`은 셈에서 빠집니다). 기간의 모든 샷이 `null`이면(포인트 클립 일감은 샷이 한두 개라 늘 그렇습니다) 그 사람의 모든 샷의 `vote`를 세어 5표 이상인 다수 쪽을 씁니다(`votedHand`, 같으면 모름). 그래도 정해지지 않으면 그 사람의 `hand`는 `null`이고, 라켓 팔 숫자(`elbowDeg`, `handHeight`)는 추측하지 않고 `null`입니다. 무릎과 몸통 숫자는 그대로 잽니다. 몸통 회전은 3D 값을 먼저 보아야 합니다. 2D는 옆이나 끝에서 본 선이 눌려 보여 값이 달라집니다.

### 깊이는 추정입니다

카메라가 하나이므로 3D의 깊이(z)는 MediaPipe world landmarks의 추정값입니다. 잰 값이 아닙니다. 3D 뼈대나 3D 숫자를 보이는 화면은 깊이가 추정이라고 적어야 합니다. 답의 `depthEstimated:true`가 그 표시입니다. SMPL은 쓰지 않으므로 몸 모양이 아니라 뼈대입니다.

### 공개 읽기 (PIN 없음, 이름만)

`GET /api/analysis/person/:ref/pose?tech=<기술>&a=<기간>&b=<기간>`

- `tech`는 `fore-attack` 같은 기술 열쇠입니다. 기간은 `2026-10`(그 달) 또는 `2026-09-01..2026-09-30`(양 끝 포함, 한국 날짜)입니다. 틀리면 400, 모르는 `ref`는 404입니다.
- 답: `{person:{ref,name}, depthEstimated:true, unattributedRallies, tech, at, a, b, diffs, reason}`.
- `unattributedRallies`: 이 사람의 경기에서 가까운 쪽 선수를 모르는(`nearSlot:null`) 데스크 랠리 수입니다(기간 구분 없음). 그 랠리의 샷은 누구의 표본에도 넣지 않습니다. 경기 분석(`analyzeMatch`)도 그런 포인트를 선수 숫자에서 빼고 `unattributed`에 셈니다.
- `a`, `b`: `{period, n, hand, skeletons:{d2,d3}, metrics:{d2,d3}}`. `skeletons`의 각 차원은 기준 시각 순서의 `{n, joints, counts}`이고, `joints`는 관절마다 평균 좌표 또는 `null`, `counts`는 그 평균 뒤의 장면 수입니다. `metrics`도 기준 시각 순서입니다.
- `n`은 그 기간에 공 맞는 순간의 2D 장면이 있는 샷 수입니다. 데스크 랠리의 샷만 셉니다. 같은 포인트는 데스크 랠리를 쓰고, 경기 날짜로 기간을 나눕니다.
- `diffs`: `{d2,d3}`, 기준 시각마다 B에서 A를 뺀 숫자입니다.
- 어느 기간이든 `n`이 5보다 작으면 비교하지 않습니다. `diffs`는 `null`이고 `reason`에 까닭이 적힙니다. `a`, `b`의 `n`과 뼈대는 그대로 옵니다. 숫자는 5장면 이상 본 관절로만 재므로, 비교가 되어도 어떤 숫자는 `null`일 수 있습니다.

## 화면: 선수

코드: `public/player-view.js`(화면 하나, 그리기와 도구), `public/app.js`의 훅(가져오기, `viewOf`·`goUp`·popstate·`render`·`screenName`·뒤로 버튼·탭 각 한 줄, 기록 탭의 `peopleSection()` 한 줄, `bindPlayer` 한 번), `public/style.css`의 `선수` 블록. 브리프와 `Layout:`은 `DESIGN.md` 5절.

- 들어가는 곳: 기록 탭의 `선수` 카드(`GET /api/analysis/people`, 접히는 목록, 이름과 `label`·경기 수·마지막 경기 날), 분석 시트 경기 줄의 두 이름(공개 목록에서 보이는 이름으로 찾고, 같은 이름이 둘이면 기록 탭의 목록으로 안내). 화면 스택에 쌓여 왼쪽 위 뒤로와 브라우저 뒤로가 같은 곳으로 돌아가고, 분석 시트와 서로를 열 수 있어요(나중에 연 쪽이 위).
- 데이터: `GET /api/analysis/person/:ref?month=&period=`를 달이나 기간 단위가 바뀜 때 다시 읽고, `GET /api/analysis/person/:ref/pose?tech=&a=&b=`를 기술이나 기간이 바뀜 때 다시 읽어요. 기간 A·B의 기본은 지난달과 이번 달(KST). 이름만 보여요.
- 달력: 월요일부터 7칸, 경기가 있는 날은 올린 패널에 `나:상대` 스코어와 승·패, 경기가 더 있으면 `+n경기`, 클립이 있으면 ▶ n. 누르면 그날 경기가 아래에 나오고 `분석 보기`가 시트를 열어요(대회 경기는 `기록/경기`, 갤러리는 `'g'`). 선택은 채운 톤과 ✓.
- 추이: `주별`/`월별` 세그먼트, 선 그래프(승률은 노랑 실선과 동그라미, 기술 성공률은 흰 점선과 네모)와 같은 숫자의 표(기간, 경기, 승률 승/경기, 기술 성공률 성공/샷). 기술 성공률은 여섯 기술의 샷을 다 더한 비율이에요.
- 이긴 경기와 진 경기: 한 표에 두 열(경기 수, 서브·리시브 득점률, 기술 6줄, 길이 4줄, 평균 샷 속도), 비율 뒤에 n.
- 자세 비교: 기술 select, 기간 A·B(`type=month`), 기준 시각 세그먼트(0.77초 전 · 0.4초 전 · 공 맞는 순간). 2D 캔버스에 두 기간의 평균 뼈대를 겹쳐 그려요(A 노랑 실선 동그라미, B 흰 점선 네모; 선 모양이 다르므로 색만으로 가르지 않아요). 3D 캔버스는 끌어서 돌리고(외부 라이브러리 없이 직교 투영) 끌지 않고도 돌리는 버튼이 있어요. 네 숫자(팔꿈치 각, 무릎 굽힘, 몸통 회전, 라켓 손 높이)는 3D 뼈대가 있으면 3D에서, 없으면 2D에서 재고 A, B, B−A와 n을 같이 적어요. `reason`이 있으면 그 문장을 표 위에 보이고 B−A는 비워요. 깊이가 추정이라는 문장과 `unattributedRallies`가 있으면 그 수를 적어요.
- 이름 바꾸기 · 합치기(PIN을 넣은 기기만): 이 사람의 열쇠는 같은 이름의 후보(이름만, 등록된 선수, 대기열의 열쇠, 연결의 열쇠)를 `GET /api/analysis/person/<열쇠>`(x-pin)로 물어 `person.ref`가 같은 것으로 찾아요. 못 찾으면 열쇠를 적게 하고 같은 방법으로 확인해요. 새 이름을 치면 `열쇠 → 새 열쇠 · 경기 n개가 새 이름으로 보여요` 미리 보기, 붙일 선수를 고르면 두 사람의 경기 수와 합친 뒤 수를 미리 보여요. `POST /api/players/rename`, `POST /api/players/merge` 뒤에는 적힌 연결이 `적힌 연결`에 나오고 각각 `되돌리기`(`DELETE /api/players/aliases/:from`)가 있어요. 결과는 카드 안 문장으로 보이고 토스트는 없어요.
