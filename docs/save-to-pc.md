# 저장: 앱 주인(서버를 띄운 사람)의 컴퓨터에 남겨서 공유하기

저장 방식: **랠리 기록 + 하이라이트 영상(랠리 구간만, 카메라 원본) + 오버레이 정보 트랙**, 공유 링크로 보기(다시 볼 때 오버레이를 그림). 아래대로 구현됨(`save-server.js`, `public/js/recorder.js`, `public/js/replay-track.js`, `public/js/replay.js`, `public/js/app.js`, 설정·기록 화면).

## 구현된 것 (설계와 다른 점 포함)

- 열쇠 전달: 1회용 설정 링크로 전달한다. `bun scripts/make-setup-link.mjs`가 새 링크를 `~/.config/pingpong-vision/setup-link.txt`(0600)에만 쓴다(화면에 안 찍음). 링크는 한 주소 `…:10000/#setup=<토큰>`(대회 앱 `/`가 카메라 화면으로 넘김), 10분 만료, 한 번 쓰면 무효(다시 열면 "설정 링크가 이미 쓰였거나 시간이 지났어요"). 앱이 열리자마자 주소창에서 `#` 부분을 지우고 `POST /vision/api/setup`으로 한 번 바꿔 열쇠를 폰에 저장한다. 서버 디스크엔 토큰의 sha256과 만료 시각만 남는다. 이미 앱이 열려 있는 탭에 링크가 들어와 주소의 `#` 부분만 바뀌어도(`hashchange`, 뒤로 가기 캐시 복원 `pageshow`) 똑같이 바꾼다. `#setup` 뒤가 잘리거나 바뀌어 모양이 틀리면 조용히 넘어가지 않고 "설정 링크 모양이 달라요"를 띄운다. 안내 문구는 버튼 아래 첫 화면 밖에 있어서, 새 안내가 뜨면 그 줄까지 스크롤해 보이게 한다. 시험: `qa/sw-update-e2e.mjs`(옛 서비스 워커가 깔린 상태의 첫 열기 포함).
- PIN으로 켜기(2026-10-30): 대회 PIN이 통과한 브라우저는 PC 저장도 켜진다. 앱이 `POST /vision/api/pin-save {pin}`을 보내면 비전 서버가 그 PIN을 대회 앱의 `/api/pin/verify`로 그대로 넘긴다(비전 서버가 본 기기 주소를 `X-Forwarded-For` 한 값으로 같이 넘기므로 5번 틀리면 1분 잠금과 전체 상한이 대회 앱 PIN 입력과 같이 세어짐. 그 주소는 127.0.0.1(Tailscale serve)에서 온 요청이면 `X-Forwarded-For`의 마지막 값, 아니면 접속 주소이고, `cf-connecting-ip`는 쓰지 않음). 통과하면 그 브라우저 전용 토큰(43자)을 주고, 앱은 열쇠 자리에 저장한다. 업로드 열쇠 자체는 브라우저로 안 나간다. 서버는 `~/.config/pingpong-vision/save-grants.json`(0600)에 토큰의 sha256과 PIN의 HMAC(업로드 열쇠로 서명)만 둔다(최대 64개). 토큰은 그 HMAC이 대회 앱 데이터(`PPV_TOURNAMENT_DATA`, 기본 `tournament/data/tournament.json`의 PIN)와 맞을 때만 통한다. PIN이 바뀌면 그 PIN으로 받은 토큰은 모두 401이 되고, 화면은 "이 기기 권한이 끊겼어요. 대회 PIN을 넣으면 켜져요". 틀린 PIN이나 잠김은 401(`code: pin|locked`), 대회 앱이 꺼져 있으면 503이다. 업로드 상한·401·413·507 검사는 열쇠와 똑같다. 1회용 링크로 받은 업로드 열쇠는 PIN과 상관없이 그대로 켜져 있다. 첫 화면 PC 저장 칸에 PIN 칸이 있고, 같은 브라우저에서 대회 앱에 PIN을 넣은 적이 있으면 카메라 화면이 열릴 때 저절로 켜진다. 저장된 옛 PIN은 한 번 거절되면 버려서 잠금을 부르지 않는다. 환경 변수 `PPV_TOURNAMENT_URL`(기본값 없음, 운영은 `deploy.env`), `PPV_TOURNAMENT_DATA`. 시험: `test/save.test.js`, `qa/save-pin-e2e.mjs`(Chromium·WebKit).
- 시험 서버(2026-10-30): PIN 확인은 `PPV_TOURNAMENT_URL`로 가고 PIN 데이터는 `PPV_TOURNAMENT_DATA`에서 읽는다. `PPV_TOURNAMENT_URL`은 기본값이 없다(그날 시험 PIN이 운영으로 가서 127.0.0.1 칸을 잠갔다). 없으면 PIN으로 켜기는 503으로 꺼져 있고 아무 곳에도 보내지 않는다. 운영은 `deploy.env`에 두고 `start.sh`가 서비스 환경으로 넘기며, 값이 없으면 `start.sh`가 FUNNEL_PORT처럼 멈춘다(`off`면 끔). 시험 스크립트는 격리 대회 주소와 데이터를 둘 다 준다.
- 켜짐 표시: 앱이 열릴 때(그리고 다시 온라인이 될 때) 폰에 있는 열쇠로 `GET /api/key-check`를 물어, 204면 "PC 저장: 켜짐 ✓", 401이면 "꺼짐"(열쇠가 맞지 않음), 답이 없으면 "확인 못 함"으로 첫 화면·카메라 화면 위 칩(`PC✓`/`PC꺼짐`/`PC?`)·설정에 보인다. 꺼져 있으면 "대회 PIN을 넣으면 켜져요". 올리기가 401을 받아도 꺼짐으로 바뀐다. 열쇠 값은 화면에 안 나온다. 이미 켜진 폰에서 쓰인 링크를 또 열면 "PC 저장은 이미 켜져 있어요". 시험: `qa/save-status-e2e.mjs`(WebKit 폰·TV 크기).
- 열쇠: 서버가 처음 켤 때 `~/.config/pingpong-vision/upload-key`(0600)에 만든다. 사용자는 앱 **설정 → PC 저장 열쇠**에 한 번 붙여 넣는다(서버가 `/api/key-check`로 맞는지 확인). 설계의 `?save=` 링크 방식 대신 직접 입력으로 했다(주소창·기록에 열쇠가 남지 않게).
- 녹화(2026-10-31, 영상은 원본, 오버레이는 정보로 따로 저장해서 다시 볼 때 그림): 랠리가 시작될 때 `MediaRecorder`로 시작, 랠리가 끝나면 멈춘다. 영상은 카메라 그림만(오버레이 없음) 최대 960 px 폭으로 녹화한다. 같은 시간축으로 **오버레이 정보 트랙**을 따로 남긴다: 녹화한 그림마다 첫 그림 뒤 ms와 화면이 그리는 상태(이름표·발밑 문구·관절선 `players`, 궤적·LOCK `ball`, 바운드 `bounces`, 기록 칸 `rally`, 선수 패널 MOVE·손목·SHOT, 코트맵 점 `players.*.stand`, 마지막 샷, 추적 상태, 보정 모서리)를 앞 그림과 달라진 부분만 담고, 알림(엔드 교체·자리 교체 등)은 시각과 문장으로, 화면 배치(세로/가로, phone/tv, 영상 칸 위치, 채움/맞춤)는 `meta`로 담는다. 형식은 gzip JSON(`public/js/replay-track.js`, 위치 0.1 px·그 밖 소수 둘째 자리). 설정 **다시 보기 오버레이**(기본 넣기)를 "영상만"으로 바꾸면 트랙 없이 영상만 올린다. mp4(H.264)가 되면 mp4, 아니면 WebM. 한 클립 최대 14초(Safari 26 mp4 녹화가 15초 넘으면 멈춘 화면이 되는 버그 https://bugs.webkit.org/show_bug.cgi?id=315091 때문). 2026-10-31 아침의 "화면 그대로 녹화"(PR #51, `screen-rec.js`)는 이것으로 바뀌었고, 그때 올라간 클립(오버레이가 영상에 들어 있고 트랙 없음)은 예전처럼 영상만 재생된다.
- 앞 버퍼(2026-11-01, 1.1.13 → 1.1.14에서 3초): PC 저장이 켜져 있으면 녹화기가 마지막 3초 장면을 캔버스 링(긴 변 480, 최대 60MB, `public/js/frame-ring.js`)에 들고 있다가, 랠리가 시작되면 그 장면부터 클립에 그린다. 그리기는 화면 갱신 루프에서 오래된 장부터 하나씩(밀린 장은 클립 프레임 속도로), 트랙 시각은 그린 시각(PC가 저장할 때 카메라 시각으로 다시 씀, 아래 "그림 시각 다시 쓰기"), 녹화는 마지막 장 뒤 두 프레임 기다렸다 멈춘다. 클립마다 트랙 `meta.counts`에 보인·그린·건너뛴·솎은(`thinned`) 장 수와 멈춘 시간을 남긴다. 링 크기는 3초 × 클립 fps(30)장이라, 초당 34~39장을 주는 폰에서는 링이 3초 전에 차서 앞 장이 일찍 나가 앞 구간이 약 2.4초가 됐다(2026-11-04 실제 경기 클립: 모든 장이 `early`). 그래서 링은 카메라 시각 기준으로 초당 약 fps장만 받는다(다음 받을 시각보다 반 프레임 넘게 이른 장은 뺀다). 같은 메모리로 3초를 다 담고, 클립도 초당 약 30장이 된다. 이건 앞 구간을 채우는 고침이다. 메인 스레드가 막혀 그리기가 몰리면 클립 안 장 간격이 고르지 않은 것(폰 재생 끊김)은 이것으로 풀리지 않는다(모형에서 early 168/168, 최대 767ms 어긋남). 또 클립을 시작할 때 링 상태를 트랙 `meta.start`에 남긴다: 들고 있던 장 수(`held`)와 가장 오래된 장의 나이(`preRollMs`), 녹화기가 armed된 지(`armedMs`, PC 저장·실행 중·두째 카메라 아님), 링을 새로 만든 지(`ringMs`, 화면 크기가 바뀌면 새로 만든다)와 지금까지 만든 수(`rings`). 앞 구간이 짧은 클립은 이 값으로 원인(막 armed됨, 크기 바뀜)을 가른다. `off`는 녹화기가 마지막으로 꺼졌던 이유(`mode:<화면 모드>`, `no-save`, `secondary`)와 꺼져 있던 시간, `resumedMs`는 카메라가 1초 넘게 멈췄다(화면 숨김 등) 다시 장을 주기 시작한 지다. 링은 보정(모서리) 화면에서도 계속 채워서, 보정을 마치자마자 넣은 서브도 3초 앞 구간을 받는다. 카메라가 멈췄다 돌아오면 그 전 장은 버린다(클립이 시간이 끊긴 장으로 시작하지 않게). 녹화기 안 오류는 녹화만 끄고 점수는 그대로(`recSafe`, `app.js`).
- 다시 보기: `public/replay.html?clip=<공유 경로>`가 원본 영상 위에 트랙을 보고 카메라 화면 코드(`ui.js`, `hud.js`) 그대로 오버레이를 그린다. 영상이 보여 주는 그림마다(`requestVideoFrameCallback`, 없으면 `currentTime`) 그 그림의 트랙 상태를 그리므로 되감기·일시정지·끝 장면에서도 같은 그림의 오버레이다. "선수·코트"로 패널 접기·펼치기(기본 펼침), "오버레이 끄기/켜기". 대회 앱 관전의 전체 화면 다시 보기는 트랙이 있으면 이 페이지를, 없으면 예전처럼 영상을 띄운다. 공유 링크(`/s/<id>`)도 같다.
- 올리기: 기록 저장 조건과 같이 샷 2개 이상·바운드 1개 이상인 랠리만. 랠리 구간 밖 영상은 녹화 자체를 안 한다. 기록 화면에 "올리는 중 / 올림 / 못 올림", 올리면 "공유 링크"와 "지우기".
- 받는 쪽 확인: 영상 형식은 업로드가 말하는 형식이 아니라 파일 머리(mp4 `ftyp`, WebM EBML)로 판단.
- 저장: `~/pingpong-vision-saves/<id>/`에 `record.json`, `video.mp4|webm`, 트랙이 있으면 `overlay.json.gz`(모두 0600). 트랙은 `GET /vision/s/<id>/overlay`가 평범한 JSON으로 준다(브라우저에 DecompressionStream이 없어도 됨). 올릴 때는 gzip(CompressionStream이 있으면) 또는 JSON 그대로, 둘 다 아니면 415. 다시 보기는 영상을 먼저 틀고 트랙이 오면 오버레이를 붙이며, 8초 안에 못 받거나 깨졌으면 영상만 보인다.
- 그림 시각 다시 쓰기(2026-11-04, `clip-retime.js`): 폰은 클립 그림을 메인 스레드에서 그리고, 캔버스 스트림은 그린 순간을 그림 시각으로 찍는다. 분석(자세 읽기 약 50ms)이 페이지를 잡는 동안엔 못 그리고, 풀리면 몰아서 그린다. 그래서 탁구장 클립은 그림이 10~12ms, 50~65ms 간격으로 저장됐고, 카메라 시각과 최대 287ms 어긋났다. 업로드를 받으면 PC가 트랙의 `cam`(그림마다 카메라 시각)으로 영상의 그림 시각을 다시 쓰고(`ffmpeg -c copy`, setts, 다시 인코딩 없음), 트랙 `t`와 알림 시각도 같이 옮긴다(`meta.retimed: "cam"`). 그림과 트랙 프레임은 순서대로 짝짓는다. 캔버스 스트림의 첫 그림(첫 그린 그림보다 2~3ms 앞)이나 마지막 한 장은 남는 그림으로 둔다. 따로 튄 그림 몇 장(50장에 1장, 연속 아님)은 받아 준다. 트랙이 없거나, `cam`이 빠졌거나, 이웃 장의 `cam` 간격이 그린 간격보다 1초 넘게 크거나(카메라가 멈췄다 돌아온 첫 장이 멈추기 전 분석 시각을 달고 온 경우, `cam-jump`), 장수·짝이 안 맞으면 그대로 두고 `record.json`의 `retime.skipped`에 이유를 적는다. 다시 쓰면 `retime: { pictures, shiftMs }`를 적는다. 이미 저장된 클립은 `bun scripts/retime-saves.mjs --dir=<저장 폴더>`로 목록을 보고, `--apply --backup=<새 폴더>`로 바꾼다. 먼저 바꿀 폴더를 백업하고 `SHA256SUMS`를 쓴 뒤 바꾼다. 바꾼 다음 장수·길이·디코딩을 확인하고 `report.json`에 남긴다. `--restore=<백업>`은 sha256을 확인하고 원본을 돌려놓는다.
- 지우기: 기록의 "지우기"가 PC의 폴더를 지운 뒤(열쇠 필요) 폰 기록에서도 지운다. 영상과 트랙이 한 폴더라 같이 지워진다. 지운 링크는 404.
- 상한: 영상 200 MB, 기록 1 MB, 트랙 4 MB, 최대 300개, 합계 5 GB(트랙 포함), 시간당 60번.

## 지금 원칙과의 관계

- 지금 앱은 "영상은 폰 밖으로 나가지 않는다"를 지키고, 서버에 받는 경로가 아예 없다(`server.js`).
- **기록만**(랠리 시간·샷 수·속도·바운드 위치·MOVE, 숫자 JSON)은 영상이 아니어서 이 원칙과 부딪히지 않는다.
- **하이라이트/전체 영상**은 원칙을 바꾸는 일이다. 사용자가 직접 고른 경우에만, 설정에서 사용자가 켰을 때만 보낸다(기본 꺼짐). 다른 사람 얼굴이 찍힐 수 있다는 안내를 켤 때 한 번 보여 준다.

| 서버 | 앱 서버(HTTPS 역방향 프록시/터널 뒤) | 기존 `/vision` 아래에 둔다. 대회 앱은 그대로. |
| 주소 | `POST /vision/api/save/<비밀값>` (받기), `GET /vision/s/<비밀값>/` (사용자용 목록·내려받기·공유) | 인터넷에 공개된 주소이므로, 추측할 수 없는 비밀값이 경로에 있어야만 열린다. |
| 비밀값 | 32바이트 난수(base64url 43자). `~/.config/pingpong-vision/save-token`에 두고, 서버가 처음 켤 때 없으면 만든다. | 로그인 화면 없이 앱 주인(서버를 띄운 사람)만 쓰는 링크. 유출되면 파일을 지우고 새로 만들면 끝. |
| 폰에 링크 넣기 | 사용자에게 한 번 `…/vision/?save=<비밀값>` 링크를 준다. 앱이 그 값을 폰 저장소에 넣고 주소창에서 지운다. | 사용자 기기에 설치·로그인 없이. |
| 저장 위치 | `~/pingpong-vision-saves/YYYY-MM-DD/HHMMSS-<종류>.(json|mp4|webm)` | 날짜별로 앱 주인이 컴퓨터에서 바로 찾을 수 있게. 저장소(git)·공개 폴더 밖. |
| 크기 제한 | 기록 1 MB, 하이라이트 200 MB, 전체 영상 2 GB(사용자가 고를 때만) | 프록시·디스크 보호. 넘으면 413과 한국어 안내. |
| 공유 | 목록 페이지에서 파일마다 "공유 링크 만들기": 따로 만든 짧은 비밀 링크 `GET /vision/f/<파일비밀값>` (7일 뒤 만료, 언제든 취소) | 전체 목록 권한을 남에게 주지 않고 파일 하나만 보낼 수 있게. |
| 지우기 | 목록에서 지우기, 30일 자동 삭제(사용자가 켤 때) | 남의 얼굴이 담긴 영상을 오래 두지 않게. |
| 보안 | 비밀값 없는 요청 404, 같은 출처만(CSP `connect-src 'self'` 그대로), 업로드는 Content-Type 확인, 파일 이름은 서버가 만든다(사용자 입력 안 씀), 경로 탐색 차단, 분당 요청 수 제한 | 인터넷에 열린 받는 경로의 기본 방어. |

## 앱 쪽 흐름

1. 정지하면 랠리 기록이 지금처럼 폰에 남는다.
2. 비밀값이 있으면 "PC에 저장" 버튼이 기록 화면에 생긴다. 누르면 기록 JSON을 보낸다(기록만인 경우 자동 저장도 가능).
3. 영상이 허락되면: 카메라 영상을 `MediaRecorder`로 폰 안에서 녹화하고, 랠리 구간(시작 0.5초 전 ~ 끝 0.5초 뒤)만 잘라 하이라이트로 보낸다. 아이폰 Safari는 `video/mp4`(H.264)로 녹화된다. 보내는 중 진행률, 실패 시 다시 보내기.

## 남은 결정 (사용자가 정함)

- 올릴 것: 기록만 / 하이라이트 영상 / 전체 영상.
- 자동 저장 여부, 보관 기간.
